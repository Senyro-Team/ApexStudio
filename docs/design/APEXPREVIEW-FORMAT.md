# Apex Preview Export

`.apexpreview` is the file-only handoff between Apex Studio and Apex Livery Lab. The Lab has its own local catalog of supported Job Vehicles; the archive contains no model geometry, workspace data, credentials, or absolute paths.

## Version 1 archive

The archive is a ZIP file with `manifest.json` at its root and one PNG for every current image in the selected livery folder:

```text
manifest.json
assets/image-001.png
assets/image-002.png
```

The UTF-8 manifest contains `format: "apexpreview"`, `formatVersion: 1`, exporter, project and livery identities, a stable vehicle catalog ID and display name, `category: "JobVehicle"`, livery colors, and relative image entries. A placed image has `role: "panel"` and a canonical `panelId` such as `WindowLeft1`; an unplaced image has `role: "reference"` and `panelId: null`. Original image names are retained as metadata. Archive paths are generated by Apex Studio and never use the source file path.

## Vehicle scope

Only livery-supported entries in the Law Enforcement, Fire Department, and Department of Transportation groups are exportable to the Lab. Civilian vehicle IDs are not part of the Lab catalog. If a vehicle ID is missing, unknown, or outside those supported Job Vehicle groups, export fails with a message instead of substituting a different vehicle.

## Import behavior in Apex Livery Lab

The Lab validates the archive manifest and every referenced PNG, looks up the vehicle by stable ID, loads its local model, applies the colors, and places matching panel images. Unsupported panel IDs remain references for manual assignment. An unknown vehicle ID requires the user to choose a Job Vehicle manually and is reported as such. Import remains local to the browser session; it does not connect to Apex Studio or a server.

The Lab catalog build script consumes the official Apex vehicle catalog and the local extracted model set. It keeps only supported Law, Fire, and DoT vehicles; the generated catalog contains 84 entries and excludes Civilian vehicles.
