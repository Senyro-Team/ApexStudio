# Apex Studio

<!-- impeccable:product-schema 1 -->

## Platform

web

React-based desktop interface inside Tauri, Windows first. The value above describes the interface technology, not a hosted website. Cross-platform readiness is an architectural requirement, not a released-platform claim.

## Stack

Confirmed baseline: Tauri 2, React, TypeScript, Rust and SQLite. Foundation and project-management implementation authorised 2026-10-22.

## Users

Livery creators and designers working with ER:LC assets, Roblox uploads and ERLCX publishing.

## Product Purpose

Keep projects, visual notes, source assets and publishing preparation together in one local workspace. Essential local work must function offline without an Apex account.

## Operating Context

One active workspace. Imports copy files into managed storage while preserving originals. Backups cover SQLite and files. Roblox uploads are available independently of projects, initially for personal accounts. ERLCX publishing content is authored in the app and transferred to an unpacked Chrome extension that fills the current step on request; users continue and publish themselves.

## Capabilities and Constraints

Initial modules: projects, project/general notes, assets, package import/export, Roblox uploads and ERLCX livery publishing assistance. Projects have names, descriptions, tags, multiple ER:LC vehicles, reference links, creation dates and optional deadlines. Catalogue suggestions include all current vehicles with livery support labels, including unknown support. Assets accept all file types; Roblox upload requires validated PNGs. Notes use visual editing with usual Markdown features including images and links.

Commissions, payments, workflow management, analytics, AI and collaboration are outside the release scope. Spacious revision approved as the foundation direction; user authorised implementation. All interface text and default content are English. Provider IDs and unverified capabilities must not be invented.

## Brand Commitments

Apex Studio retains Apex Designs branding. Supplied assets under design/ are binding references. Forks retain in-app branding under separately scoped permission; unrelated reuse is forbidden. Use a similar freely licensed font, not an unlicensed copy of the original banner font. Archivo is a researched candidate pending visual review. Code licensing remains undecided; source-available restrictions are specified in docs/planning/CURRENT-SCOPE.md.

## Product Principles

- Local records and original source files stay under user control.
- Shared core owns business rules; interfaces present understandable actions and recovery.
- Uploading and publishing remain deliberate, reviewable operations.
- Brand expression supports long editing sessions and clear content.
- Interface copy is concise and functional: no filler/taglines such as "Pick up where you left off."
- Development progress, phase references, future-feature promises and implementation commentary belong in documentation, never in the app. Do not present unimplemented features as working features.
- Phase 3 authorised 2026-10-22: apply the copy rule throughout current and new screens; implementation status stays in documentation.
